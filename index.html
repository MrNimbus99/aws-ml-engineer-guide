Domain 1: Data Preparation for Machine Learning (ML)
A company is ingesting streaming clickstream data for real-time ML inference. The data arrives at 10,000 records per second and must be processed with sub-second latency. Which ingestion solution should be used?
  • Amazon SQS with EC2 consumers
  • Amazon S3 with batch uploads every minute
  • ✓ Amazon Kinesis Data Streams with Lambda for processing
  • AWS Glue streaming ETL jobs
Show Explanation
✓ Why correctKinesis Data Streams is designed for real-time streaming data ingestion with sub-second latency. Lambda can process records in near real-time as they arrive, meeting the 10,000 records/second throughput and sub-second latency requirements.
✗ Why A is wrongAmazon SQS is a message queue service designed for decoupling application components, not for high-throughput streaming ingestion. SQS standard queues have higher and less predictable latency compared to Kinesis Data Streams, and SQS does not natively support the ordered, high-throughput streaming patterns required here.
✗ Why B is wrongBatch uploads every minute introduce at least 60 seconds of latency, which far exceeds the sub-second requirement. S3 is object storage optimized for durability and cost, not real-time streaming ingestion.
✓ Why C is correctThis is the correct answer.
✗ Why D is wrongAWS Glue streaming ETL jobs run on Apache Spark Structured Streaming, which introduces higher startup and per-micro-batch latency than Kinesis Data Streams with Lambda. Glue streaming is better suited for complex ETL transformations rather than low-latency ingestion.

✗ Why D is wrongRemoving the minority class eliminates the ability to detect it entirely. The goal is to improve detection of the minority class, not ignore it.

✗ Why D is wrongManually reviewing CloudWatch Logs does not scale and does not provide statistical analysis of data distribution changes. Model Monitor automates this detection with statistical methods.
